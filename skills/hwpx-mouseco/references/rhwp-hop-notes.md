# rhwp / HOP 참고 메모

## 목적

이 문서는 `hwpxskill`이 실제 HWP/HWPX 편집기·렌더러가 어떤 수준까지 구현하고 있는지 참고할 수 있도록 만든 실무 메모다.

중요:
- XML 태그 의미, 패키지 구조, 참조 구조의 source of truth는 여전히 한컴 공식 문서와 KS X 6101이다.
- `rhwp`, `HOP`는 구조 의미의 최종 근거가 아니라, 실제 편집/렌더링 엔진이 무엇을 중요하게 다루는지 보여주는 구현 참고 자료다.

## hwpxskill 개선에 주는 시사점

### 1. 문서 작성은 텍스트 치환 문제가 아니다
`rhwp` README에서 강조되는 기능은 단순 텍스트 파싱보다 아래에 가깝다.
- paragraph layout
- indentation
- alignment
- tables
- numbering / bullets
- object placement
- header / footer

즉 `hwpxskill`도 문서 작성 지시를 할 때 단순히 본문 문장을 채우는 수준에 머물면 안 된다.
문단, 표, 개체, note, 구획 배치를 함께 생각해야 한다.

### 2. 표와 박스는 예외가 아니라 핵심 표현 수단이다
실제 에디터가 중요하게 다루는 단위가 문단만이 아니라 표, 텍스트박스, 이미지, 개체 배치라는 점은 다음 원칙을 강화한다.
- 비교는 표로
- 절차는 단계형 정리로
- 일정은 계획표로
- 주의/참고는 note 문단이나 박스로
- 핵심 요약은 상단 요약영역으로

즉 "예쁘게" 쓴다는 뜻은 불릿만 예쁘게 맞추는 것이 아니라, 내용에 맞는 표현 수단을 고르는 것이다.

### 3. 글머리 위계는 역할 체계로 다뤄야 한다
`rhwp`가 번호/글머리표와 문단 레이아웃을 별도 중요 기능으로 다룬다는 점은 `hwpxskill`의 방향과 맞닿아 있다.
- 기호를 외우는 것보다 문단 역할을 먼저 판정
- 상위 항목 / 하위 항목 / 세부 설명 / note 역할 구분
- 같은 템플릿 안의 exemplar 문단을 재사용

### 4. "지원되는 표현 형식"을 더 넓게 봐야 한다
앞으로 `hwpxskill`은 최소한 아래 표현 형식을 항상 검토 대상으로 둔다.
- 일반 본문 문단
- 섹션 제목
- 상위 bullet
- 하위 bullet
- 세부 설명 bullet
- 주의/참고 note
- 요약 박스
- 비교표
- 일정표
- 역할 분담표
- 단계형 정리
- 간단한 도식형 배치

단, 실제 템플릿에 이미 있는 구조를 우선 재사용한다.

### 5. 편집기 관점의 품질 기준을 가져올 수 있다
실제 편집기/렌더러 참고 관점에서 `hwpxskill` 품질은 아래를 함께 봐야 한다.
- 문단 위계가 자연스러운가
- 줄바꿈 후 내어쓰기가 깨지지 않는가
- 표와 note가 본문과 역할 구분이 되는가
- 한 페이지 안에서 정보 밀도가 균형적인가
- 모든 정보를 bullet로만 우겨넣지 않았는가

## 사용 원칙

- 구조/태그/패키지 의미를 설명할 때는 한컴 공식 문서를 우선 인용한다.
- 표현력, 편집기 감각, 실제 배치 판단을 보강할 때는 `rhwp`와 `HOP`를 구현 참고 자료로 활용한다.
- `hwpxskill`은 이 프로젝트들을 그대로 복제하는 것이 아니라, "어떤 표현 단위를 중요하게 봐야 하는가"를 배우는 데 사용한다.
- 스킬 폴더 안에 별도 Python을 두지 않는 원칙은 유지한다.
