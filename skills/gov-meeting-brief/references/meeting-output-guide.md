# 회의결과 정리 기준

## 결정사항과 의견 구분

- 결정사항: 회의체나 책임자가 실행 방향을 확정한 내용
- 합의사항: 참석자 간 이견 없이 동의된 내용이나 최종 승인 전 단계일 수 있음
- 검토사항: 실행 전 추가 자료, 법령, 예산, 일정 확인이 필요한 내용
- 의견: 특정 참석자의 제안이나 우려로, 조직 결정으로 쓰면 안 되는 내용

표현 예시:

- 결정사항: `OO 사업은 6월 중 시범 운영을 추진한다.`
- 합의사항: `부서 간 자료 제출 양식은 단일 서식으로 맞추는 방향에 공감하였다.`
- 검토사항: `개인정보 영향 여부는 관련 부서 검토 후 확정한다.`
- 의견: `현장 적용성을 높이기 위해 사용자 교육이 필요하다는 의견이 있었다.`

## 후속조치 작성 기준

후속조치는 반드시 실행 단위로 쓴다.

좋은 예:

- `정보화팀: API 연계 가능 여부를 5월 15일까지 확인`
- `사업부서: 시범 운영 대상 기관 후보 3곳을 선정`

나쁜 예:

- `추진 검토`
- `계속 협의`
- `필요시 반영`

담당자나 기한이 없으면 `확인 필요`로 둔다. 임의 배정하지 않는다.

## 간부 브리핑 변환

간부 공유용은 아래 순서가 안전하다.

1. 오늘 결정해야 할 것
2. 이미 정리된 것
3. 남은 리스크
4. 필요한 지원 또는 승인

회의 세부 발언보다 책임·일정·리스크를 먼저 배치한다.

## 민감정보 처리

- 주민등록번호, 연락처, 계좌, 내부 시스템 계정은 삭제하거나 `[비공개]`로 표시한다.
- 불필요한 실명은 직위나 역할로 바꾼다.
- 징계, 민원, 감사, 인사 관련 발언은 원문 인용을 최소화하고 사실 중심으로 쓴다.
- 외부 공개 가능 문서와 내부 공유 문서는 표현 수위를 분리한다.

## 품질 점검

완료 전 아래를 확인한다.

- 결정사항과 의견이 섞이지 않았는가
- 담당자와 기한이 원문 근거 없이 만들어지지 않았는가
- 회의 목적과 안건이 앞부분에 보이는가
- 후속조치가 실제 실행 단위인가
- 민감정보나 불필요한 개인 평가가 남아 있지 않은가
