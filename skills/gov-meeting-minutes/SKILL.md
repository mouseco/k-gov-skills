# Gov Meeting Minutes

## 목적

회의 메모나 녹취록을 **공문서형 회의록 PDF**로 정리한다. 보고서처럼 꾸미지 말고, 회의 기록물답게 표와 선 중심의 단정한 형식으로 만든다.

기본 산출물은 다음 구조다.

- 1쪽: 회의록 요약본
- 2쪽 이후: 상세 발언록
- 별도 요청 시: HTML 원본과 PDF를 함께 제공

## 먼저 확인할 것

녹취록에 `참석자 1`, `참석자 2`처럼 익명 발언자가 있으면 바로 PDF를 만들기 전에 발언자 식별을 확인한다.

1. 각 익명 발언자의 주요 발언 취지와 역할을 짧게 요약한다.
2. 사용자에게 이름이나 직함을 기억하는지 묻는다.
3. 사용자가 알려주면 회의록과 상세 발언록에 반영한다.
4. 사용자가 모른다고 하거나 익명 처리를 원하면 `참석자 1`, `참석자 2` 또는 `발언자 A`, `발언자 B`를 유지한다.

예시 질문:

```text
참석자 1은 문서 수정 방향을 지시한 검토자, 참석자 2는 초안 작성 의도를 설명한 실무자처럼 보입니다. 이름이나 직함을 기억하시나요?
```

## 기본 workflow

1. 입력을 회의 메모, 전사 원문, 요약형 메모 중 하나로 분류한다.
2. 회의명, 일시, 장소/방식, 참석자, 안건을 추출한다.
3. 익명 발언자가 있으면 사용자에게 발언자 식별을 확인한다.
4. 1쪽 회의록에는 아래 항목만 담는다.
   - 회의 목적
   - 주요 논의내용
   - 결정사항
   - 후속조치
   - 확인 필요사항
5. 2쪽 이후 상세 발언록에는 시간, 발언자, 발언 요지를 표로 정리한다.
6. 원문이 불명확한 내용은 단정하지 말고 `확인 필요` 또는 `전사 내용상 의미 불명확`으로 표시한다.
7. HTML을 먼저 만든 뒤 PDF로 렌더링한다.
8. PDF를 실제로 열거나 페이지 이미지로 렌더링해 하단 여백, 빈 회색 박스, 불필요한 페이지 분리를 확인한다.

## 출력 기준

- 기본 파일명: `meeting-minutes-YYYYMMDD.pdf`
- 형식: A4 PDF
- 디자인: 흑백 중심, 표와 선 중심, 공문서형
- 금지: 둥근 카드형 UI, 과한 색상, 보고서형 요약 카드, 서명란 기본 삽입
- 페이지 번호: 우측 하단에 작게 `1 / N` 형식
- 하단 회색 박스나 빈 장식 영역을 만들지 않는다.

## PDF 구성

### 1쪽: 회의록

```text
회의명 / 작성일
일시 / 장소
참석
안건

1. 회의 목적
2. 주요 논의내용
3. 결정사항
4. 후속조치
5. 확인 필요사항
```

### 2쪽 이후: 상세 발언록

```text
시간 | 발언자 | 발언 요지
```

상세 발언록은 가능한 한 불필요한 페이지 분리를 피한다. 단, 가독성을 해칠 정도로 글자를 줄이지는 않는다.

## 렌더링 스크립트

구조화 JSON이 준비되면 다음 스크립트로 HTML/PDF를 만든다.

```powershell
python -X utf8 skills\gov-meeting-minutes\scripts\render_minutes_pdf.py --input <minutes.json> --output <minutes.pdf> --html <minutes.html>
```

입력 JSON 예시는 `examples/ai-demand-meeting-minutes.sample.json`을 참고한다.

## 품질 점검

완료 전 아래를 확인한다.

- PDF 페이지 수가 의도와 맞는가
- 각 페이지 하단에 회색 빈 박스가 없는가
- 1쪽이 보고서처럼 과장되지 않고 회의록으로 보이는가
- 상세 발언록이 여백이 충분한데도 불필요하게 다음 페이지로 넘어가지 않았는가
- 익명 발언자 식별 확인 결과가 반영되었는가
- 담당자·기한·결정사항을 원문 근거 없이 만들지 않았는가

## 상세 기준

회의록 문장, 발언자 식별, 상세 발언록 정리 기준이 필요하면 `references/minutes-writing-guide.md`를 읽는다.
