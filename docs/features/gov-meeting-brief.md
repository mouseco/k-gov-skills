# gov-meeting-brief

`gov-meeting-brief`는 공공기관 회의 메모, 녹취 요약, 회의자료를 회의결과보고와 후속조치 목록으로 정리하는 스킬이다.

## 해결하는 문제

회의 후 남는 자료는 보통 발언 순서대로 흩어져 있어 바로 보고하거나 실행하기 어렵다. 이 스킬은 회의 내용을 안건별로 묶고, 결정사항·후속조치·확인 필요사항을 분리해 책임과 다음 일을 분명하게 만든다.

## 언제 쓰는지

- 회의 녹취나 자동 전사본을 회의결과보고로 바꿀 때
- 회의 메모에서 액션아이템을 뽑을 때
- 간부에게 공유할 5줄 요약이 필요할 때
- 결정사항과 단순 의견을 구분해야 할 때
- 공공기관 내부 공유용 문체로 다듬어야 할 때

## 입력과 출력

입력:

- 녹취록, 회의 메모, 참석자 발언 요약, 회의자료, 안건지

출력:

- 회의 개요
- 핵심 요약
- 안건별 논의 결과
- 후속조치 목록
- 확인 필요사항
- 공유·보고 시 유의사항

## 기본 workflow

1. 회의 목적과 안건을 확인한다.
2. 발언을 안건별로 재배열한다.
3. 결정사항, 논의 요지, 후속조치, 확인 필요사항을 분리한다.
4. 담당자와 기한은 원문 근거가 있을 때만 확정한다.
5. 민감정보와 불필요한 개인 평가를 제거한다.
6. 보고 목적에 맞춰 회의결과보고, 간부 브리핑, 액션아이템 목록 중 하나로 정리한다.

## 사용 예시

```text
이 회의 메모를 회의결과보고 형식으로 정리해줘. 결정사항과 후속조치를 분리해줘.
```

```text
이 녹취 요약에서 부서별 액션아이템만 뽑아줘. 담당자와 기한이 없으면 확인 필요로 표시해줘.
```

```text
간부 보고용으로 5줄 요약과 남은 쟁점만 정리해줘.
```

## 실패 모드와 보완 방법

- 담당자나 기한이 원문에 없으면 임의로 만들지 않고 `확인 필요`로 표시한다.
- 발언자가 불명확하면 안건 중심으로 정리하고 개인 귀속을 피한다.
- 법령, 예산, 개인정보 쟁점이 있으면 확정 표현 대신 추가 검토 필요로 둔다.
- 회의자료만 있고 실제 논의 내용이 없으면 `자료 기준 정리`라고 명시한다.

## 보안·민감정보 주의사항

실제 내부 회의록, 인사·감사·민원 관련 내용, 개인정보가 포함된 원문은 공개 저장소 예시로 넣지 않는다. 스킬에는 가상 사례와 공개 가능한 문장만 둔다.
